# 交互逻辑分析

## 当前逻辑问题

### 问题 1: 单击和双击的处理
- **当前**：双击时先触发单击，然后触发双击，导致侧边栏会先打开
- **需要**：双击时不应该触发侧边栏

### 问题 2: 侧边栏没有缓存
- **当前**：每次打开侧边栏都会重新调用 API
- **需要**：侧边栏内容应该缓存，再次打开时立即显示

### 问题 3: 单击已展开节点的逻辑
- **当前**：单击已展开节点时，会打开侧边栏，但不会再次展开（这是对的）
- **需要**：应该只打开侧边栏，使用缓存内容

## 正确的交互逻辑

1. **生成初始图谱后，已生成的内容会一直存在** ✅
2. **单击某个节点**：
   - 打开解释窗口（侧边栏）
   - 如果节点未展开，同时展开节点（生成子节点）
   - 不影响已存在的节点
3. **关闭解释窗口后，双击该展开节点**：
   - 收起新节点
   - 不会触发解释窗口（识别单击和双击的区别）
4. **重新单击该节点**：
   - 立即打开解释窗口
   - 内容不变（内容来自于缓存）
5. **双击时可正常再次展开节点**：
   - 双击已收起的节点，应该展开
   - 双击已展开的节点，应该收起
6. **其他节点同样遵守这个逻辑**

## 修复方案

1. **添加双击延迟处理**：使用 setTimeout 延迟单击处理，如果检测到双击则取消单击
2. **添加侧边栏内容缓存**：缓存每个节点的侧边栏内容
3. **优化单击逻辑**：
   - 单击时：打开侧边栏 + 如果未展开则展开节点
   - 双击时：收起/展开节点，不打开侧边栏
